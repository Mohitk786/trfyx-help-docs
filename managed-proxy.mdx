The managed proxy serves `script.js` from a subdomain of **your** site (for example `t.yoursite.com`) instead of `app.trfyx.com`. Ad blockers that block known analytics hosts are less likely to stop the script. You do not run any proxy code. Trfyx issues the HTTPS certificate after the proxy is Active.

Open **Settings → Installation**. The Managed proxy card is on that tab. You need permission to configure the site, and a Starter plan or above.

<Note>
  Most sites should use this. The [self-hosted proxy guides](/proxy-guide) are only for teams that already forward requests through their own server.
</Note>

## What you will do

1. Pick a subdomain of your site and click **Enable proxy**.
2. Add **two** DNS records (CNAME and TXT) in your DNS provider.
3. Click **Check status**.
4. Copy the tracking snippet again if you already installed the old one.

## Set it up

<Steps>
  <Step title="Choose a subdomain">
    On **Settings → Installation**, find **Managed proxy**. Type a hostname that belongs to your site, such as `t.yoursite.com`.

    Rules the form enforces:

    - It must be a **subdomain** of the site domain (or an extra domain you added). `yoursite.com` itself is not allowed.
    - A short, plain name such as `t` or `cdn` is harder for simple blocklists to guess than `analytics` or `tracking`.
    - Two sites cannot share the same hostname.

    Click **Enable proxy**. The status becomes **Pending**.
  </Step>
  <Step title="Add two DNS records">
    The card now shows the exact records. Add both in the DNS zone for your site (the `yoursite.com` zone, not a different domain).

    | Type | Host to type | Value |
    | --- | --- | --- |
    | `CNAME` | The prefix only, for example `t` | The target shown in the card. Copy it. Do not invent one. |
    | `TXT` | `asuid.` plus that same prefix, for example `asuid.t` | The long value shown in the card. Copy it. |

    Type the Host **exactly** as the card shows it. Do not add `.yoursite.com` again. If you type `asuid.t.yoursite.com` in a panel that already sits on the `yoursite.com` zone, the real name becomes `asuid.t.yoursite.com.yoursite.com` and the check fails.

    <Warning>
      If you use Cloudflare, set both records to **DNS only** (grey cloud). **Proxied** (orange cloud) will not pass the check.
    </Warning>

    This is not a URL redirect and not a forwarding rule. It must be a real CNAME and a real TXT.

    DNS can take up to 10 minutes.
  </Step>
  <Step title="Click Check status">
    When both records are live, click **Check status**.

    Trfyx looks up:

    - The CNAME on your subdomain. It must point at the target from the card (or resolve to the same IP addresses).
    - The TXT on `asuid.` plus your full subdomain. The value must match the card exactly.

    If a record is missing, the card says which one it is still waiting for (`Waiting for CNAME`, `Waiting for TXT`, or both). Fix that record and click **Check status** again.

    When both match, the status becomes **Active**. Trfyx then allows HTTPS on that hostname and issues the certificate on the first visit.
  </Step>
  <Step title="Use the new snippet">
    After the proxy is **Active**, the tracking snippet at the top of **Settings → Installation** already uses your subdomain:

    ```html
    <script
      defer
      data-website-id="YOUR_WEBSITE_ID"
      data-domain="yoursite.com"
      src="https://t.yoursite.com/script.js">
    </script>
    ```

    Keep `data-domain` as your real site. Change only `src` to your proxy hostname (the form does this for you).

    You do **not** add `data-api-url`. The script sends events to `/api/collect` on the same host it was loaded from. Heatmaps, replays, and web vitals use that same host.

    If you installed the script before the proxy was Active, copy the snippet again and replace the old tag.
  </Step>
  <Step title="Confirm it is working">
    1. Open a real page on your site (not the proxy hostname).
    2. Open Developer Tools → Network and reload.
    3. Confirm `script.js` loads from your subdomain.
    4. Confirm a request goes to `/api/collect` on that same subdomain.
    5. Confirm a visit appears in Trfyx.

    You can also click **Verify installation** on the same settings tab.
  </Step>
</Steps>

<Tip>
  Tracking is off on localhost unless the script has `data-allow-localhost="true"`. Test on the live site, or add that attribute only while you test.
</Tip>

## If Check status stays Pending

| The card says | What to check |
| --- | --- |
| Waiting for CNAME | Host is the prefix only (`t`, not `t.yoursite.com` twice). Type is CNAME, not a redirect. Cloudflare is DNS only. |
| Waiting for TXT | Host is `asuid.t` in the `yoursite.com` zone. The value is copied from the card with no extra quotes your provider does not expect. |
| Waiting for CNAME and TXT | Both records are missing, in the wrong zone, or not public yet. Wait a few minutes and click **Check status** again. |

Leave both records in place after the proxy is Active. The check does not run again, but the CNAME is what browsers use.

## If the script still comes from app.trfyx.com

The page is still serving the old snippet. Copy the snippet from **Settings → Installation** after the badge says **Active**, and replace the tag you already shipped.

A Content Security Policy must allow your proxy hostname in `script-src` and `connect-src`.

## Remove the proxy

<Steps>
  <Step title="Remove it in Trfyx">
    On the Managed proxy card, click **Remove**. Confirm. The badge disappears and the snippet at the top switches back to `https://app.trfyx.com/script.js`.
  </Step>
  <Step title="Update the snippet">
    If you already shipped the proxy URL, copy the standard snippet again so visitors are not sent to a hostname that no longer serves the script.
  </Step>
  <Step title="Delete the DNS records">
    Remove the CNAME and the `asuid.` TXT in your DNS provider. They are unused after you remove the proxy.
  </Step>
</Steps>

Your existing analytics data stays. Removing the proxy only changes where the script is loaded from.
